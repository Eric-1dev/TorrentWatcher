# qBittorrent

Приложение подключается к Web UI qBittorrent по API v2 и умеет применять обнаруженные
обновления. Интеграция необязательна: без адреса и учётных данных приложение работает
как раньше — только фиксирует обновление.

## Что происходит при обновлении

1. Скан скачивает новый `.torrent`, видит, что infohash изменился, и сохраняет файл.
2. Если авто-применение включено (или нажата кнопка «Применить»), `TorrentApplyService`
   находит в клиенте старую раздачу по `SupersededInfoHashV1`.
3. Старая раздача удаляется через `POST /api/v2/torrents/delete` с `deleteFiles=false`:
   файлы на диске остаются.
4. Если новой раздачи ещё нет, она добавляется (`POST /api/v2/torrents/add`) с той же
   `savepath`, категорией и тегами; `autoTMM=false`, чтобы путь не переопределился.
5. Выполняется `recheck` (пересчёт хешей, уже скачанное переиспользуется) и `resume`.
6. `AppliedInfoHashV1` и `AppliedAtUtc` сохраняются; ошибка клиента попадает в `ApplyError`
   и не делает проверку торрента ошибочной. Повтор — на следующем скане или вручную.

Авто-применение не импортирует раздачи, которых в клиенте ещё не было: если
`AppliedInfoHashV1` и `SupersededInfoHashV1` пусты, автоматика ничего не делает.
Первое добавление — кнопкой «Применить»; если старой раздачи в клиенте нет, новая
добавляется с папкой по умолчанию qBittorrent.

## Настройки

На экране «Настройки»:

| Поле | Смысл |
|---|---|
| Адрес Web UI | `http://plex.local:8080` — должен быть доступен из контейнера |
| Логин / пароль | учётная запись qBittorrent; пароль шифруется Data Protection |
| Применять автоматически | без него работает только кнопка «Применить» в таблице |
| Проверить соединение | логин + `GET /api/v2/app/version`, показывает версию или ошибку |

Смена адреса, логина или пароля сбрасывает результат прошлой проверки.

## Сеть

- **qBittorrent на хосте.** Docker Desktop: `http://host.docker.internal:8080`.
  Linux: добавьте `extra_hosts: ["host.docker.internal:host-gateway"]` и используйте
  тот же адрес. DNS-имя хоста (`plex.local`) тоже подойдёт, если оно резолвится
  из контейнера и Web UI слушает внешний интерфейс.
- **qBittorrent в Docker.** Общая сеть и `http://qbittorrent:8080`; публиковать порт
  Web UI наружу не обязательно.
- **Порт 8080.** По умолчанию его занимает qBittorrent. TorrentWatcher публикуется на
  хосте на 8088 (`APP_PORT`), внутри контейнера Kestrel слушает 8080 — конфликта нет.
- **Host header validation.** Включённая проверка ломает запросы по имени контейнера
  или `host.docker.internal` (`401/403`). Выключите её или добавьте используемый хост
  в список.
- **Bypass authentication for localhost.** Из контейнера клиент не является localhost;
  полагаться на этот режим нельзя — задайте логин и пароль.

Проверка из контейнера:

```bash
docker compose exec torrentwatcher curl -i http://host.docker.internal:8080/api/v2/app/version
```

## Ошибки

| Код | HTTP | Когда |
|---|---|---|
| `QBITTORRENT_NOT_CONFIGURED` | 409 | нет адреса, логина или пароля (ручное применение) |
| `QBITTORRENT_AUTH_FAILED` | 409 | неверные данные, бан после попыток, отказ 403 |
| `QBITTORRENT_UNAVAILABLE` | 502 | таймаут, сетевой сбой, неожиданный ответ |

Все три сценария при автоматическом применении не прерывают скан.

## Границы

- Рутрекер остаётся единственным источником `.torrent`; qBittorrent не скачивает файл сам.
- История версий не хранится: только последний `.torrent`, текущий и применённый infohash.
- При удалении записи из TorrentWatcher раздача в qBittorrent остаётся.
- Авторизации у приложения нет; учётные данные qBittorrent защищены только доступом к хосту
  и `/data` (пароль — ещё и Data Protection).
